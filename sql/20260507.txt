인덱스를 사용하는 이유
- 데이터가 많은 테이블에서 select를 빠르게 하기 위해 사용한다.
- 데이터가 적을 때는 차이가 거의 없지만 많아지면 차이가 엄청 커진다.

인덱스 생성 문법
create index 인덱스명 on 테이블명 (컬럼);

인덱스 확인
show index from 테이블명;

인덱스 삭제
drop index 인덱스명 on 테이블명;

※ 테이블 생성 시 K를 지정하면 자동으로 인덱스가 만들어진다.
※ UNIQUE 제약조건도 자동으로 인덱스가 만들어진다.

단점
- 별도의 저장공간 필요
- INSERT, UPDATE, DELETE 작업에서 느려질 수 있음

아래 조건에 자주 사용되는 컬럼이라면 인덱스를 걸면 좋다.
1. WHERE
2. JOIN
3. ORDER BY
4. GROUP BY

단일 컬럼 인덱스
CREATE INDEX idx_employee_department ON employee(department);

복합 인덱스
CREATE INDEX IDX_EMPLOYEE_DEPT_SALARY ON employee(department);

내가 작성한 SELECT 문장이 INDEX를 사용하는지 확인하는 방법
ㄴ> 문장 앞에 EXPLAIN 작성

SubQuery
- SQL 안에 또 다른 SQL을 넣어 사용하는 기법
- 메인쿼리(Main Query) 안에 포함되는 부속 SELECT문
- 괄호 안에서 실행, 먼저 실행한 뒤 그 결과를 메인쿼리가 사용

서브쿼리가 사용되는 경우
- 특정 조건을 찾기 어려울 때
- 집계 결과를 다시 조건으로 사용하고 싶을 때
- 존재 여부를 판단할 때

다중컬럼 서브쿼리를 사용하는 이유
- 단순 단일컬럼 비교로는 문제가 생길 수 있음

다중 컬럼 비교의 핵심
(컬럼1, 컬럼2)를 하나의 세트로 비교한다.
두 컬럼의 관계까지 유지

FROM절에서 사용되는 서브쿼리(inline view)
- 서브쿼리로 조회된 값을 테이블처럼 사용한다.

inline view를 사용하면 좋은 경우
- 중간 결과를 재사용
- 복잡한 통계의 처리
- 정렬/필터링

상관 서브쿼리(Correlated Subquery)
- 서브쿼리가 바깥쪽 쿼리의 값을 참조하는 서브쿼리
- 서브쿼리가 혼자 실행될 수 없고, 바깥쪽 쿼리의 각 행마다 반복 실행되는 구조
