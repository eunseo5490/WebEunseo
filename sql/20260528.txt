ㄴ 정규화
# 물리 데이터 저장소 설계하기
ㄴ 반정규화 : 테이블이 너무 나눠져 있어서 JOIN을 너무 많이해서 오히려 조회 성능이 떨어져서 테이블을 합치는 작업
중복테이블 추가
- 집계 테이블 추가
- 상태 컬럼을 담고 있는 테이블을 생성
- 특정 부분만을 포함하는 테이블 추가
테이블 조합
- 항상 같이 사용되는 두 개 이상의 테이블을 하나로 합치는 것
테이블 분할
- 수직분할 : 컬럼별 사용 빈도의 차이가 많은 경우 자주 사용되는 컬럼과 그렇지 않은 컬럼으로 분류하여 테이블 분할
- 수평분할 : 특정 범위별 사용 빈도 차이가 많은 경우 해당 범위별로 테이블을 분할하는 방법
테이블 제거
- 테이블 재정의나 컬럼의 중복화로 더 이상 사용되지 않는 테이블이 발생하면 삭제하기
컬럼 중복
- 필요한 해당 테이블이나 컬럼을 중복하여 추가
- 다른 테이블에 있는 컬럼을 현재 테이블에도 추가로 저장하는 것
# 물리 데이터 모델링하기
논리 모델링을 통해 얻은 내용을 데이터베이스에 사용할 수 있는 물리데이터 모델로 변환

엔티티 -> 테이블로 변환
ㄴ 일반적으로 테이블과 엔티티 명칭은 동일하게 하는 것을 권고함
속성 -> 컬럼으로 변환
ㄴ 속성의 명칭과 반드시 일치할 필요는 없으나, 개발자와 사용자 간의 의사소통을 위하여 가능한 표준화된 언어를 사용해야 함
ㄴ SQL 예약어 사용은 피해야 함
ㄴ SQL 문장의 가독성을 높이기 위해 컬럼의 명칭은 가능한 짧으면 좋음
UID -> 기본키(PK)로 변환
ㄴ 
관계 -> 외래키(FK)로 변환
ㄴ 외래키로 설정된 컬럼명은 보통 기본키의 이름을 그대로 사용
ㄴ 다른 의미를 가진다면 변경 가능함
컬럼 타입 및 길이를 정의
ㄴ 넣으려는 데이터의 크기를 파악해서 컬럼의 길이를 지정
반정규화 적용 여부를 검토

물리 데이터 저장소 구성하기
테이블 제약조건
PK, FK, CHECK, DEFAULT, NOT NULL, UNIQUE

기본키와 외래키로 관계를 맺고 있는 테이블에서의 제약조건

삭제할 때
- 참조된 기본키의 값이 삭제될 경우 어떻게 처리할 지 정하는 규칙
고객이 삭제되면, 그 고객의 주문 데이터는 어떻게 할 것인가

CASCADE
- 부모테이블의 데이터가 삭제되면, 그 데이터를 참조하고 있던 자식 테이블의 데이터도 함께 삭제되는 방식

파티션
- 하나의 큰 테이블을 내부적으로 여러 족가으로 나누어 저장하는 기술
- 겉으로는 하나의 테이블로 보여진다.

파티션이 필요한 이유
- 대용량 데이터를 여러 영역으로 나누어 저장함으로써 조회 시 필요한 데이터만 읽어 성능을 향상시킴
- 백업/복구/삭제와 같은 관리 작업을 효율적으로 수행

인덱스
목적 : 데이터를 빠르게 탐색
개념 : 데이터 탐색 속도 향상
데이터를 정렬된 구조로 저장
책의 목차/찾아보기

파티션
목적 : 데이터를 나눠서 관리
개념 : 읽을 데이터 범위를 축소

파티션의 종류
범위 분할
- 특정 컬럼 값의 범위에 따라 데이터를 나누어 저장하는 방법
