Index
- 조회를 빠르게 하기 위한 목적으로 사용
- where, order by, group by에 많이 사용되는 속성에 대해 미리 접근 위치를 기록해놓는다.
- 실제 조회를 할 때 해당 컬럼이 사용되면 index가 자동으로 사용
- insert, update, delete에 대해서는 좀 불리하다.

- 인덱스 생성
create index 인덱스명
on 테이블 (컬럼);

- 테이블에 해당된 인덱스 확인
show index from 테이블명;

- 인덱스 삭제
drop index 인덱스명 on 테이블명;

Sub Query
- sql문 안에 sql문이 있는 것
- 특정 조건을 다른 테이블 조회 결과로 판단할 때
- 평균값, 최대값 같은 계산 결과를 기준으로 조회할 때
- join 없이 단계적으로 데이터를 조회하고 싶을 때

종류
- 단일 행 서브쿼리 : 결과 1개
- 다중 행 서브쿼리 : 결과 여러개
ㄴ 사용하는 기호 : in(여러 값 중 하나), any(하나라도 만족), all(모두 만족)

- 다중 컬럼 서브쿼리 : 컬럼 여러개
- 상관 서브쿼리 : 바깥 쿼리와 연결됨
- from절 서브쿼리 : 가상 테이블처럼 활용

Join
- 정규화를 통해서 분리된 테이블에서 공통된 컬럼을 기준으로 연결해서 조회하는 기능

inner join
- 두 테이블에서 조건이 일치하는 데이터만 조회

left outer join
- from절에 작성된 테이블의 데이터는 전부 조회하고, join된 테이블의 데이터는 조건이 맞는 데이터만 조회
- 없는 데이터 쪽은 NULL로 표시

right outer join
- left와 right는 방향만 바뀐 것이기 때문에 테이블 순서를 바꿔서 left를 더 많이 사용

cross join
- 두 테이블에 들어있는 데이터의 모든 조합을 만듦

on절이 두 테이블을 연결하는 기준

외래키가 없어도 조인은 가능하나 무결성을 해칠 수 있으므로 권장하지 않음
                             ㄴ☆ 시험

두 테이블에 같은 이름의 컬럼이 있으면 어느 테이블에서 조회하려는 것인지 명확하게 작성해야 함

LEFT OUTER JOIN
ON VS WHERE

select customer_name, product_name

left outer join orders o
on c.customer_id = o.customer_id

-> 조건이 일치하지 않는 데이터는 조회가 안됨

select customer_name, product_name

left outer join orders o

left outer join product p

AUTO_INCREMENT
- 숫자 값을 자동으로 1씩 증가시켜서 입력해주는 속성
- 데이터를 추가할 때마다 직접 번호를 입력하면 번거롭기 때문에 사용을한다.
- 반드시 숫자 타입의 컬럼에만 붙여야한다.
- 인덱스가 있어야 하기 때문에 PK와 함께 사용한다.
- 한 테이블에 하나만 사용할 수 있다.
- 직접 값을 넣을 수도 있다.
INSERT INTO board(board_id, title, content)
values (100, '관리자 공지', '직접 번호 입력');
그 다음 자동 증가 값은 보통 101부터 시작한다.
- 중간 번호는 재사용하지 않는다.
1	첫번째글
2	두번째글
3	세번째글

delete from board
where board_id = 3;

새 글을 추가하게 되면 board_id가 4로 추가된다.
- AUTO_INCREMENT는 연속 번호 보장용이 아니라 고유 식별자 생성용이다.

- INSERT 했다가 ROLLBACK 해도 다음 번호로 건너뛴다.
- 테이블 생성 후 다음 자동 증가값을 바꿀 수 있다.
ALTER TABLE 테이블명 AUTO_INCREMENT = 1000;
이후 새 데이터는 1000부터 들어갈 수 있다.

- 현재 AUTO_INCREMENT 값 확인하기
SHW TABLE status LIKE '테이블명';

- 마지막으로 생성된 번호 확인하기
select LAST_INSERT_ID();

LIMIT
- 조회 결과를 제한하는 절
- 몇개까지만 보여줘

SELECT *
FROM 테이블
LIMIT 5;

ORDER BY와 함께 많이 사용된다.
내림차순으로 정렬해서 상위 5개만 조회해라

데이터가 몇백만건 들어있는 테이블에서 LIMIT이 없으면 위험할 수 있다.

LIMIT 시작위치,개수
LIMIT 개수 OFFSET 시작위치

페이징처리할 때 사용
SELECT *
FROM BOARD
ORDER BY BOARD_ID DESC
LIMIT 0, 10; 0개 건너뛰고 10개 조회

SELECT *
FROM BOARD
ORDER BY BOARD_ID DESC
LIMIT 10, 10; 10개 건너뛰고 10개 조회

일반 SQL문은 한문장씩 실행이 된다.

Sorted Program
- MySQL 서버 안에 저장해두고 실행하는 프로그램의 단위
Stored Procedure	여러SQL 작업을 묶어서 실행하는 프로시저

Stored Program의 핵심 구조
DELIMITER //
CREATE PROCEDURE hello()
BEGIN
    SELECT 'Hello MySQL Stored Program' AS message;

변수를 선언하는 DECLARE
DECLARE 변수명 자료형 DEFAULT 기본값;
DECLARE v_name varchar(50) DEFAULT '홍길동';


BEGIN ~ END 블록의 가장 앞부분에 작성해 한다.
일반 SQL문 뒤에 선언하면 오류가 난다.

BEGIN
DECLARE v_num int default 0;

select '시작';
END;


변수에 값을 넣는 SET
SET 변수명 = 값;


IN은 외부에서 값은 받아오는 매개변수
CREATE PROCEDURE 프로시저명(IN 매개변수명 타입)

OUT은 프로시저 내부에서 만든 밧을 외부로 내보내는 매개변수
CREATE PROCEDURE 프로시저명(OUT 매개변수명 타입)

INOUT은 값을 받아오고, 수정한 뒤 다시 내보내는 역할
CREATE PROCEDURE 프로시저명(INOUT 매개변수명 타입)
